# 升级、归属与恢复

源仓库和已安装技能分开。只有通过安装器实际写入的文件才属于本工具；相同的外部文件不会被认领。收据保存相对路径/哈希，修改前保存备份，再写 pending 日志。异常时尝试还原；断电后用 recover。路径越界、绝对路径、Windows junction/reparse point 均拒绝。

## 从旧个人技能迁移

1. 先用 `-DryRun` 检查目标。不同的旧技能没有 v2 安装收据，安装器会保留并将候选内容放到技能根 `.godot-agent-kit/proposals/`。
2. 对比旧技能与新包，保留有价值的个人配置和修改。把旧目录备份到该宿主技能发现根之外；确认新版本要替代它后，再将旧目录移走并安装。不要简单给目录加后缀仍放在技能根中，那会产生重复技能。
3. 仅迁移工具路径到本机 JSON；模型权重、虚拟环境和原有 local.json 不进仓库。安装可 `-Config` 写入新的私有 local.json。
4. 已有游戏不需要重新初始化。需要更新某个游戏的 dev 技能时用 `-Skills dev`，先处理其现有自定义指令；不会因此创建 Desktop 实例、改引擎或改游戏资源。

安装器不自动接管没有收据的旧版本，也没有绕过冲突的 force 覆盖开关。改源仓库后使用相同 agent/scope/路径重跑是正常升级。卸载之后只移除确实归本工具所有且未修改的文件；保留用户文件与恢复记录，空目录可自行整理。

## 升级失败与回滚

- `install` 返回 2：本次技能内容没有应用，审阅列出的冲突和 proposals。不要把该结果称为安装成功。
- `rollback`：恢复最后一次实际变更前的文件与收据。若安装后有人再次改过文件，拒绝整个回滚，避免覆盖新工作。
- `recover`：只用于 `.godot-agent-kit/pending.json` 指向的未完成事务。核验当前文件等于旧版或预期新版，再恢复旧版；检测额外修改或损坏备份时保留现场。
- `uninstall`：删除未修改的受管理文件，保留其他文件；返回 2 表示有修改文件保留，输出明确清单。
- 回滚和卸载不会卸载 Godot、Desktop、Python、模型，不动游戏和用户全局 MCP 配置。

安装中断时不要删除 `.godot-agent-kit/history` 或 pending。清理永久备份需在不再需要恢复时由用户决定，不混入本轮临时清理。

项目初始化的 `.bootstrap/state.json` 是另一层归属，保护生成的项目文件。补齐模式保留入口/场景/测试/需求/架构；用户文件冲突生成 `.bootstrap/proposals/`，审阅后用 `--keep-existing` 保留为用户管理。旧 Desktop schema 迁移仍执行原技能 references/maintenance.md 的显式流程。
