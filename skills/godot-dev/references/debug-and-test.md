# 调试与行为验收

用于错误修复、回归和实现交付。选择能证明本次需求的检查，不以数量或全部绿色日志替代玩家结果。

## 定位真实失败

记录引擎版本、入口、操作顺序、预期/实际、相关设置与最小可重复条件。先区分解析/导入、配置、运行时、输入/时序、渲染、声音或环境问题。

读取第一条相关错误和调用栈，检查实际场景树、导出引用、process_mode、可见性、信号订阅和当前状态。可用编辑器 Remote tree、断点、项目测试脚本或已发现的 Godot MCP；工具不可用时明确降级，不假装读过实时场景。

一次验证一个可证伪假设：最小复现 → 观察状态/连接/时间线 → 最小修复 → 相同复现复测 → 相关回归。不要看到空引用就到处加 `if null` 掩盖漏配置；必须区分可选依赖与破坏契约的缺失。

## 按风险选层次

| 变化 | 有意义的证据 |
| --- | --- |
| 规则、数值边界、状态转换 | 公共接口输入/输出、不变量、重复/非法操作；随机算法固定 seed |
| 节点/资源/信号组合 | 真实 PackedScene 实例，注入必要依赖，观察事件和状态；不 mock 被测组件 |
| 异步/暂停/切场景 | 真实信号/帧驱动，有界超时；等待中取消、退出、重试 |
| UI/输入 | 实际显示与真实输入路径；布局/焦点/按钮可达；直接调用回调只证明回调逻辑 |
| 可编辑性 | 临时副本修改 → 保存 → 从磁盘读回 → 运行变化及两实例隔离 |
| 声音/画风 | 技术数据与真实视听分别记录 |
| 文件 I/O | 独立路径、失败及恢复；不碰正式玩家数据 |

沿用现有 SceneTree/GUT/GdUnit4 测试；小项目可使用现有轻量脚本。实际需要 fixture、断言或测试发现能力时才引入固定兼容版本框架。不要仅因社区偏好就预装插件、强制迁移所有测试或为简单文案新增测试。

高价值业务缺陷尽量先让回归复现失败，再修复；测试通过公共 API 验证规则，不把实现复制到测试里。测试自己的连接/生命周期约定，不把测试引擎内置函数正确性当游戏覆盖率。技能维护中的引擎语义探针另记，不能计入游戏验收。

## 验证结果要能追溯

- 运行 `tools/check.ps1`，导入后做真实运行。检查退出码、日志错误、成功标记和实际执行测试数；进程 exit 0 不保证 GDScript 没报错，零测试或超时不能算成功。
- 配置/纯解析通过不证明节点路径与运行行为；仅启动主场景不证明其他页面或完整游戏。对子场景提供其约定依赖，不把脱离使用前提的独立启动失败误判为产品缺陷。
- 测试会创建节点、连接、文件和全局暂停状态；结束时释放/恢复。处理 `await` 超时，避免测试挂死和失败后污染下一项。
- 需要视觉时在实际 renderer/窗口运行，保留少量能说明问题的截图/观察；headless 不代替 shader 实际表现。声音听审能力不足时记录未验证。
- 只在受影响内容变更、失败或残留疑问时扩展/重复检查，不为增加通过数反复跑同一套。

报告采用“验收项 → 操作/命令 → 观察结果 → 证据 → 未验证边界”。区分代码测试、工具语义探针、人工/代理实际观测与尚未执行的评测场景；不能用静态文档检查宣称未来代理行为已验证。
