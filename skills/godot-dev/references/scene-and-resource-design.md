# 场景与资源：让修改发生在编辑器中

用于新增/重构场景、配置、可复用组件、序列化及 `@tool` 预览。项目 docs/development.md 是交付判据；本页补充容易遗漏的实现细节。

## 先确定谁拥有内容

| 内容 | 默认载体 | 需要考虑的边界 |
| --- | --- | --- |
| 固定 UI、角色外观/碰撞、关卡布置 | `.tscn` 的节点和子场景 | 打开源场景能理解和预览；场景自身拥有内部路径 |
| 同类对象的动态数量 | 导出的 `PackedScene` + 实例化 | 数据填充不应重新用脚本搭一遍整棵外观树 |
| 物品/角色/关卡定义、曲线、素材引用 | 类型化 `.tres` / 内嵌 Resource | 实际独立编辑或复用时才拆外部资源；不要为每个标量造类 |
| 当前生命、冷却、流程状态 | 实例字段或专用 RefCounted/节点 | 与只读定义分离，不复制第二套权威状态到 UI |
| 跨场景常驻服务 | 明确生命周期的根节点或 Autoload | 证明它需要常驻；功能内对象无需全局化 |

拆场景的理由是可独立编辑、复用、替换或职责边界；不是超过固定节点数。具有相同骨架的变体可使用浅层场景继承；只调整参数时优先覆盖属性或替换 Resource。不把每个输入、变量和方法拆成一个组件。

父级可通过导出节点引用或明确 `configure(...)` 传入外部依赖。组件内部 `$Visuals/Icon` 或 `%Icon` 可用；唯一名仍有场景所有者作用域，不能当全局寻址。固定源场景的信号可保存到 `.tscn`，运行实例间关系在组装层连接；两种方式都应能找到和验证。

## Inspector 与共享资源

- 为需要设计人员调整的字段提供具体类型、单位、范围、分组及有意义默认值。资源脚本独立成文件；需要 Inspector 创建/反序列化时 `_init` 不依赖必填外部参数。
- 直接导出 Texture2D、AudioStream、PackedScene 等真实资源引用。只有大型可选内容确需延迟加载时才使用路径/ID 目录，并说明策略，不把所有资源改为脚本路径字典。
- 同路径资源通常共享缓存。修改内存中共享对象会影响其他引用者，**不会仅因赋值就自动写回磁盘**；写盘取决于明确保存操作。
- `duplicate()`、`duplicate(true)`、`duplicate_deep()` 与 Local to Scene 不是同义词；嵌套数组、字典、外部资源的复制策略随 API/版本而定。保持定义只读通常最简单；确需可变资源时用两实例试验验证具体对象图。运行后再设置 Local to Scene 不会追溯拆开已有实例。
- Resource 可以有验证方法、查询和信号；“资源保存配置”不等于禁止所有方法。不要把场景树依赖或不断变化的角色状态塞进共享定义。

## 持久化场景必须读回

可编辑 `.tscn` 允许用文本或编辑时工具生成。工具构建只发生在制作阶段，产物应保存为正式场景，游戏不需要先运行该生成器。

- 文本中的 `parent` 决定层级；缩进不决定层级。资源 ID、节点类型、脚本、信号 source/target 都必须真实解析。
- `PackedScene.pack(root)` 只打包正确归属于该场景的节点。通过 `add_child` 创建供保存的新节点后设置合适的 `owner`；不要粗暴覆盖已有嵌套实例的所有权。
- 检查 `pack()` / `ResourceSaver.save()` 返回值，再从磁盘重新加载/实例化，断言需要编辑的节点、导出值、素材和固定信号仍在。内存里存在不等于已经保存。
- 保留已有 `.uid` 和导入设置；新增 UID 让引擎生成。移动文件时优先编辑器；使用文件工具则同时处理 sidecar、场景/脚本/动画/项目引用，重新导入并检查路径与 UID 指向一致。仅旧缓存能运行不算迁移完成。

## 编辑器预览

只有需要预览或配置告警时才加 `@tool`。用 `Engine.is_editor_hint()` 隔离游戏输入、音频、存档和外部操作；setter 在节点 ready 前可能运行，更新预览前检查就绪。资源 `changed` 连接在替换引用时解除旧对象，避免重复监听。必要的 `_get_configuration_warnings()` 指出未接资源/组件，更新配置时刷新。

验收取代表性编辑：移动/重排控件后信号仍工作，换素材后重新打开仍显示新素材，调参数后行为变化，两实例互不污染。交付“改什么 → 打开什么场景/资源 → 哪个 Inspector 字段”。

官方查阅入口（相对 `docs/godot/<主次版本>/`）：`tutorials/best_practices/scene_organization.md`、`node_alternatives.md`（同目录）、`tutorials/scripting/resources.md`、`scene_unique_nodes.md`（同目录）、`tutorials/plugins/running_code_in_the_editor.md`、`classes/class_packedscene.md`、`class_resource.md`、`class_node.md`。

## 文件组织与显式迁移

新项目默认“按类型＋功能子目录”，具体分类见项目 README 和 docs/development.md。场景、行为脚本保留对应的功能相对路径及名称，Resource 类脚本放 scripts、配置实例放 resources、媒体放 assets。目录分开不改变组件所有权和编辑入口；已有结构只有用户明确要求才迁移。

迁移时建立旧→新路径清单，更新动态路径、测试、工具、编辑指南和素材来源的目标位置；保留原始生成记录与历史验收证据。除当前工程重新导入外，在不含旧 .godot 的临时副本验证场景/Resource 可加载及主流程可运行，不能让缓存掩盖断链。用哈希验证素材、用路径归一化后的内容比较验证未改玩法与配置；最后清理本轮副本并保留紧凑映射。
