# 动画、音频与反馈

用于表现接入和播放逻辑；制作新文件另读素材生产。先沿用项目的画风、节奏与声音方向，反馈服务于操作可读性，避免为了“丰富”增加影响判断的闪烁、抖动和长锁输入。

## 选择可编辑的表现载体

| 需求 | 首选 | 注意 |
| --- | --- | --- |
| 固定多属性时间轴、过场、开门 | AnimationPlayer / AnimationLibrary | 动画轨道和时长可在编辑器调整，核验路径和 RESET/初始状态 |
| 精灵帧动画 | AnimatedSprite2D / SpriteFrames | 图集切帧、尺寸、pivot、速度与循环设置统一 |
| 连续运动混合、角色动画状态图 | AnimationTree | 使用关联 AnimationPlayer 的动画；避免两套播放控制同时争夺属性 |
| 依赖运行目标的淡入、飞行、数值变化 | 绑定节点的 Tween | 新操作取消旧 Tween；不复用已经完成的 Tween |
| 简单视觉粒子 | 粒子节点/材质资源 | 效果可预览；共享材质的运行修改需隔离 |

动画表现和玩法状态通过明确事件协作。固定攻击/交互时机若放轨道事件，应说明权威状态和取消规则；别在脚本计时器与动画里分别结算一次。动画中断、循环、离开树都纳入等待策略，不能盲等永远不会来的 `finished`。

## 音频按用途设计

- UI/非空间音乐用 AudioStreamPlayer；需要空间衰减时选 2D/3D 播放器。固定播放器和总线布局可编辑，确有并发需求时管理声部或池，不为一声点击建立通用音频框架。
- 音乐、音效及需要的其他用途使用明确 bus，用户音量与临时 duck/fade 分开；零音量处理为真正静音。切换/重试不会重复叠曲、遗留循环或把旧场景音效带入新场景。
- AudioStream 作为资源配置；更改 loop、随机播放或参数时明确共享语义，避免影响其他实例。格式、压缩、流式与驻留内存按音乐长度/用途选择，不为所有声音强制同一格式。
- 失败、确认、受击等反馈有清楚事件来源和重复触发策略；避免长按/鼠标悬停生成无限声部。结束后释放自己拥有的播放器和临时资源。

## 技术检查与感官验收分开

技术检查：可解码、持续时间、声道/采样率、非空/非静音、峰值/削波、导入/循环设置、播放并发和总线路由。它们不能证明音色协调、音量舒适或循环无接缝。

实际听审：每个采用的音乐/音效独立试听，再听游戏里的混音、过渡、循环接缝、连触发和静音/恢复。若工具只能播放给用户而不能让代理听到，不称代理已经听审；交付可试听文件和明确未验证项。图像也要检查实际画面，生成成功不能证明风格一致。
