# 交付与本轮清理

实现任务进入收尾时读取；只讨论、评审或设计的任务不执行游戏开发或实例操作。

## 收尾交付

- 临时文件集中到本轮独有的 work/dev-<任务标识>/，记录自己创建的路径。prepare_asset.py 生成的 work/assets-staging/<asset-id>/ 也按本轮清单管理；不把正式素材最终引用留在 work/ 中。
- 更新受影响的需求验收和重要架构决定。素材按 docs/asset-pipeline.md 留档到 docs/assets/<asset-id>/，保留实际工作流、模型/节点版本、输入参考及输出哈希、许可来源和验收状态；可复用母版存到项目现有素材源目录并记录位置。
- 保存一份紧凑的 .local/dev-reports/<任务标识>.json：需求与验收结果、实际检查及证据、素材/工作流位置、采用的默认值、阻碍/未验证项和清理结果。优先复用本轮记录，不生成重复总结文件；必要证据提取后才删除原日志。
- 任务结束且队列为空后，只停止本轮为工作启动的实例；用户原本运行的实例保持原状。按资源流程仅关闭本轮创建的临时调试会话，确认进程退出与端口关闭；原先打开的 Desktop 用适配器 reopen 经 Explorer Shell 恢复正常启动，不使用 computer-use 或普通子进程重开，不终止其他任务。清理已失去用途的测试工程、请求副本、下载临时包及未采用样例；删除前核对绝对路径在批准目录内、归属明确、无目录连接逃逸、没有运行中任务和正式资源引用。
- 保留有效测试源码、正式资源/参考、工作流、许可、官方文档、.uid/导入设置、绑定与 MCP 配置、共享模型及仍用于排错的记录。不清空整个 work、.local、.godot、实例输入输出或安装缓存；不在盘符根目录新建内容。清理后检查本轮清单，将需要保留的项及理由写入摘要。
- 最后说明已实现的行为、启动/操作方式、实际验证、素材和报告位置、剩余问题；给出可检查成果，不用“可以继续”代替本次尚未完成的工作。

详细架构约定见项目 docs/development.md，资源操作和许可留档见 docs/asset-pipeline.md；不另建重复规范。
