# 存档、设置与资源加载

用于玩家数据、设置、关卡切换和加载卡顿。修改既有游戏时先保留格式、路径和兼容要求，不能为套示例更换用户存档。

## 分开定义与进度

设计者在 Inspector 编辑的定义用 Resource；玩家进度用稳定 ID 和必要状态表达，不把活节点、运行实例 ID 或完整场景树当存档协议。简单设置可用 ConfigFile；结构化进度可用 JSON 或已有格式。不要因为存在 Resources 就强制重写已有存档方案。

写入 `user://` 或明确配置的可写目录。正式数据与测试目录隔离；测试使用注入路径或隔离用户目录，不清空用户实际进度。

## 兼容与失败路径

- 明确 schema_version、字段类型、范围和缺失字段默认值；仅迁移项目实际支持的历史版本。遇到未知未来版本或不可恢复内容，保留原件并给出恢复策略，不静默当新档覆盖。
- JSON 数字/集合读入后仍需校验；节点位置、向量、Resource 引用等应有明确编码和稳定 ID 映射。
- 安全写入采用同目录临时文件、错误检查、必要 flush/读回验证，再替换主文件；根据项目风险保留上一份有效备份。替换失败仍保留旧数据，不声称所有平台均绝对原子。
- 不通过加载外部可修改 `.tres`/脚本、反序列化可执行对象解决不受信任的玩家数据。对自己的可信内容采用既定资源流程即可。
- 回归覆盖实际有关的 round-trip、旧版本、损坏/截断、缺字段、写失败与备份恢复。重置行为按用户需求保留设置或要求确认，不能在测试中触发正式重置。

## 加载与切场景

小型必要资源可 preload 或直接导出引用。只有实测启动/切关卡阻塞时才加入后台加载，避免为小资源建立服务层。

`load_threaded_request()` 后检查状态/错误，到完成再取结果；过早 `load_threaded_get()` 仍会阻塞。加载取消或目标改变时使用请求身份/运行代次丢弃过期结果；后台加载不意味着可在工作线程任意修改活动 SceneTree。

场景切换会改变树和旧引用。需要等新场景准备时查当前版本 SceneTree 完成机制，不能假定方法返回就已 ready。明确失败时保留旧页面或显示恢复入口。加载界面不能只是一张永不更新的图。

移动资源后的 UID/path、导出过滤与运行访问也要核对；原目录的缓存可以掩盖坏引用。用户要求打包时再验证对应导出，未打包不声称导出环境已覆盖。
