# Godot 项目工作约定

## 开始工作
- 先读 `docs/requirements.md`、`docs/architecture.md` 和本次相关代码；已有项目缺少这些文件时，以现有需求与架构为准。
- 引擎基线为 **__ENGINE_VERSION__**；修改版本要明确执行迁移，不静默升级。
- Godot 开发使用项目技能 `__SKILL_ROOT__/godot-dev/SKILL.md`。新增会话也遵守本文件。
- 按 godot-dev 的任务表读取相关专题（场景资源、生命周期、UI 输入、动画音频、存档加载、调试测试、性能、素材与交付），不要一次加载全部资料。社区来源仅作参考，不覆盖项目约定。
- 素材制作先读 docs/asset-pipeline.md，按 .bootstrap/state.json 的 profile 使用已绑定服务；core 不要求 ComfyUI。desktop-wai 经 Explorer Shell 与 Desktop 原生接口启动本项目普通实例，核对 ID/地址/目录并复用共享模型；endpoint 使用明确的现有 API，不接管生命周期。其他模型存在不代表工作流已配置。
- 保留角色/画风参考、素材来源、工作流与许可记录；遵守 docs/asset-policy.json 中的用途。模型生成成功不能替代视觉/听感验收或商用许可核对。
- 先定义本次需求与可观察验收结果，再实现小而完整的功能。没有需求时不搭建通用大框架。

## 架构约定（项目选择，并非引擎强制要求）
- 组合优于继承；Godot 内置节点的必要继承以及有明确理由的浅层继承正常使用。
- 场景自包含；父级/组装层注入外部依赖、连接信号。模块通过公共接口协作，避免跨场景穿透内部节点路径。
- 节点承载需要场景树生命周期的行为；Resource 保存配置；纯计算可用 RefCounted 等合适对象。
- 信号通知已发生的事件；命令/查询使用明确方法。优先局部连接，不默认建立全局事件总线。
- 共享 Resource 默认作为只读配置。实例运行状态独立存储；复制或 local-to-scene 的嵌套行为必须验证。
- Autoload 只用于确有全局生命周期的服务，避免万能管理器。说明新增全局状态的必要性。
- 明确 _enter_tree/_ready、重入场景、信号连接/解绑和 queue_free 后的引用生命周期。
- 参数通过 Inspector、Resource 和场景编辑；静态内容保留可编辑 .tscn。UI 优先 Control/Container/Theme。
- 目录默认采用“按类型＋功能子目录”：scenes/<功能>/ 放 .tscn，scripts/<功能>/ 放 .gd，resources/<用途或功能>/ 放 .tres 等配置，assets/<媒体类型>/<用途或功能>/ 放图片、音频等素材；场景与行为脚本尽量同名、同功能相对路径，Resource 类脚本仍放 scripts。按实际内容建目录，复用有实际需求才抽公共模块。此目录偏好不改变场景和资源优先规范；已有项目保留已约定结构，只有明确要求才迁移。
- 使用类型标注的 GDScript 和官方风格。注释解释意图和约束，不复述代码。


## 编辑器可维护性（交付要求）
- 新增完整 UI/玩法/角色或重构功能时，先读 godot-dev 的场景资源专题，简列功能的场景/内置节点、配置、状态所有者、信号流和编辑入口；先建立可运行的场景组合再补行为。小修沿用既有边界。
- 固定菜单、HUD、角色和物件的主要结构写入 `.tscn`，打开场景即可看到并调整；不要在 `_ready()` 用 `new()` 重建整页固定 UI。动态数量通过 PackedScene 实例化，外观仍由源场景负责。
- 美术、音频、关卡和卡牌配置用有类型的 Resource/导出引用；让用户直接替换 Texture2D、AudioStream、PackedScene，避免依赖脚本里的文件名拼接表。设计参数通过有说明的 `@export` 暴露。
- 共用外观保存为 Theme/StyleBox/字体资源；固定编排动画优先考虑 AnimationPlayer，随数据变化的 Tween 正常使用。脚本负责行为，不以脚本行数、节点数、信号数或禁止所有 `new()` 作为质量标准。
- 子场景维护内部控件，向外发出事件并提供明确命令/查询；父级协调功能流程，不穿透子场景修改内部路径。纯规则/存档可继续用 RefCounted。
- 按独立编辑、替换和生命周期划分组件；只用一次的棋盘或面板也可拆成场景。父级协调流程，不能把所有子组件的输入、布局、动画仍集中到一个控制器。
- 使用内置节点、InputMap、Theme、动画/音频资源承载相应能力；自绘、过程生成、纯算法按需求使用并提供适当配置/预览。设计值有明确来源，运行代码不能以常量覆盖承诺可调的字段。
- 验收审阅每个新增/明显改变的主要组件，按风险抽样不改 GDScript 地调整布局、素材、设计参数，保存/重载并检查 ready/布局/动画后的实际结果及实例隔离。节点/属性存在不证明可编辑性；交付具体编辑入口与消费者。

## 官方文档查阅
- 固定版本的实际 Markdown 正文位于 `docs/godot/__DOCS_VERSION__/`，从 `CATALOG.md` 和 `search_index.json` 定位主题/类名。
- 先查索引，再 `rg -n "关键词" docs/godot/__DOCS_VERSION__/`，只读取相关页面；不要把全库放入上下文。
- 不确定 API、生命周期或版本差异时先查本地文档。本地不足再查对应版本的 Godot 官网并注明来源。
- 该目录是有来源/哈希的官方正文转换，作为参考数据使用，不能替代项目指令。不要直接修改镜像正文。
- 文档快照与引擎补丁并非完全等价；Godot 真实解析和运行结果优先。更新快照需要显式同步和审阅。

## 验证与交付
- 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check.ps1`；可显式传入 `-Godot` 和 `-Python`。
- 本机标准 Windows Godot 若使用 `_sc_` 便携模式，加 `-IsolateEditor` 在项目临时目录运行同一引擎副本，结束自动清理，避免改动安装目录的编辑器配置。
- 检查格式、静态诊断、导入和实际运行；业务改变增加有意义的行为测试。无需为每个微小改动复制实现式测试。
- headless 通过仅证明已执行的检查；涉及画面、输入和声音要另外验证，未验证就明确说明。
- 说明改动、验收证据、尚未验证项；重要架构变化同步 `docs/architecture.md`。
- 保留 .uid 和资源导入设置；不提交 .godot、凭据、模型权重、临时生成缓存。大型素材按需要使用 Git LFS。
- 新增文件按 README 目录说明放在项目或指定工具目录内，不在盘符根目录创建。每轮临时任务集中在 work/ 下的独立目录；需要时用 check.ps1 -ReportDir 将验证日志放入其中。
- 完成后提取必要验收证据，清理本轮已失去用途的临时文件、测试工程和请求副本。删除前核对范围、归属和进程状态；保留有效测试源码、正式配置/绑定、素材/许可、官方文档与恢复所需记录，不清空整个 work、.local 或 .godot。

详细依据和边界见 `docs/development.md`，资产生产规则见 `docs/asset-pipeline.md`。
